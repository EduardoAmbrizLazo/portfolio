Lab 4: Digital Audio

Lab Report
Using the STM32 TIM2 timer and GPIO to play a tune through a speaker.
Author

Eduardo Ambriz Lazo

Published

September 30, 2026

Introduction

In this lab, we leveraged the MCU aboard the MicroP’s Dev Board, particularly the STM32L4xx model. With it, we can use the timer logic like a counter to trigger an output at a certain frequency. This is done via the TIM2 register built into the MCU, as well as by initializing the GPIO B pins to output a signal that powers a speaker at the desired frequency. With all these puzzle pieces, we can have the speaker play an array of notes and make a tune.

I spent approximately 14 hours on this lab altogether, including familiarizing myself with the idea and a whole lot of debugging.

Design and Testing Methodology

Using SEGGER Embedded Studio, the logic of this lab was contained in a header file and a main file. The header file is essentially a library pointing to the addresses of the MCU’s registers so the main logic can leverage them. The ones of note for this lab are the RCC, TIM2, and GPIOB registers.

There are many timers onboard the MCU, but TIM2 has 32 bits and is generally recommended so overflow doesn’t occur. We can set a constant prescaler (PSC) and then specify our frequency by altering the ARR (auto-reload register).

Naturally, we want a system that can relate pitch and duration to timer configurations and that can create 220 Hz and 1000 Hz pitches within 1% accuracy. A lot of calculations are involved in this analysis, but logically:

Maximum duration

The maximum delay is the inverse of the minimum frequency (\(T = 1/f\)). Using the minimum frequency calculated below, we get \(1/(1.164 \times 10^{-5}\ \text{Hz}) \approx 85{,}900\) seconds, or 23.86 hours.

Minimum duration

The same principle applies to the minimum duration, but with the maximum frequency: \(1/(25\ \text{kHz}) = 40\ \mu\text{s}\), so the minimum delay is about 40 microseconds.

Minimum frequency

The timer output frequency is derived by \(f_{out} = f_{clk} / (2(\text{PSC}+1)(\text{ARR}+1))\). The division by 2 is due to the nature of toggling, which is why the code uses 2 MHz rather than 4 MHz in its ARR calculation. Given that \(f_{clk} = 4\) MHz and PSC = 39, the denominator is \(80(\text{ARR}+1)\), and we should set ARR to \(2^{32} - 1\).

Therefore, \(f_{min} = 4\ \text{MHz} / (80 \cdot 2^{32}) \approx 1.164 \times 10^{-5}\ \text{Hz}\).

Maximum frequency

Since PSC = 39, let’s say the code has already set the auto-reload register (ARR). For the maximum frequency, ARR should equal 1. Using the equation above:

\(f_{max} = 4\ \text{MHz} / 160 = 25\ \text{kHz}\)

Verifying 1% frequency accuracy

To be accurate, we must minimize error. What is error in this application? Error comes from the way ARR rounds, so the relative error is \(\varepsilon = 1/(2(\text{ARR}+1))\).

To satisfy \(\varepsilon \le 0.01\), we need \(1/(2(\text{ARR}+1)) \le 0.01\), meaning \(\text{ARR}+1 \ge 50\), or \(\text{ARR} \ge 49\).

In Resources below, I linked the Desmos calculator for these calculations, but to verify 1000 Hz and 220 Hz:

  • 1000 Hz: \(\text{ARR} = 2{,}000{,}000/(40 \cdot 1000) - 1 = 49\), and since \(49 \ge 49\), the 1000 Hz note is within 1% accuracy.
  • 220 Hz: \(\text{ARR} = 2{,}000{,}000/(40 \cdot 220) - 1 = 226.273\), and since \(226.273 \ge 49\), the 220 Hz note is also within 1% accuracy.

Additional frequencies and their ARR values are in the Desmos calculator.

Checking only 220 Hz and 1000 Hz is not sufficient: ARR must be rounded to an integer for every note, and each frequency leaves a different remainder, so it’s possible a frequency in between ends up off. The error must be evaluated across every note between 220 Hz and 1000 Hz.

AI Prototype Summary

NoteInitial Prompt Response

Timers to Use (220 Hz to 1 kHz)

The STM32L432KC includes several general-purpose and advanced timers suitable for signal and PWM generation:

  • TIM2 (32-bit): High-precision general-purpose timer. Its 32-bit width provides a massive counting range, making low frequencies easily reachable without risk of counter overflow.
  • TIM1 (16-bit): Advanced-control timer. Fully capable, but includes extra complex features (break inputs, dead-time) that are unnecessary for basic audio/PWM signals.
  • TIM15 & TIM16 (16-bit): General-purpose 16-bit timers. Suitable for basic signal output, though care must be taken to ensure the 16-bit limit (65,535) isn’t exceeded when selecting prescaler values.

Best Choice & Easy GPIO Pin Mapping

TIM2 Channel 1 mapping to PA0 (Pin A0 on the NUCLEO-L432KC board) is the best choice.

  • Why: TIM2 is a 32-bit timer, giving you maximum resolution for calculating duty cycles and frequencies.
  • Pin Connection: PA0 supports AF1 (Alternate Function 1) for TIM2_CH1. It breaks out cleanly on the outer headers of the Nucleo-32 board.

Relevant Formulas

Output frequency (\(f_{\text{PWM}}\)):

\[f_{\text{PWM}} = \frac{f_{\text{TIMCLK}}}{(\text{PSC} + 1) \times (\text{ARR} + 1)}\]

  • \(f_{\text{TIMCLK}}\): Timer input clock frequency (e.g., 80 MHz standard system clock).
  • \(\text{PSC}\): Prescaler register value (0 to 65,535).
  • \(\text{ARR}\): Auto-Reload Register value (defines the period).

Duty cycle (%):

\[\text{Duty Cycle} = \frac{\text{CCR1}}{\text{ARR} + 1} \times 100\%\]

  • \(\text{CCR1}\): Capture/Compare Register value (controls when the pin toggles).

Calculation Example (\(f_{\text{TIMCLK}} = 80\) MHz)

To maintain a high counter resolution, pick a fixed prescaler value. Set \(\text{PSC} = 79\) (divides the clock down to 1 MHz, or 1 µs per tick).

For 1000 Hz output:

\[\text{ARR} = \frac{80{,}000{,}000}{(79 + 1) \times 1000} - 1 = \frac{1{,}000{,}000}{1000} - 1 = 999\]

For 220 Hz output:

\[\text{ARR} = \frac{1{,}000{,}000}{220} - 1 \approx 4544\]

Required Registers & Configuration Steps

To output a hardware PWM signal on pin PA0 without CPU overhead, configure the following registers:

Clock enable registers

  • RCC->AHB2ENR: Set bit GPIOAEN to enable the GPIOA clock.
  • RCC->APB1ENR1: Set bit TIM2EN to enable the TIM2 peripheral clock.

GPIO pin configuration (GPIOA)

  • GPIOA->MODER: Set MODER0 to 10 (Alternate Function Mode).
  • GPIOA->AFR[0]: Set AFSEL0 to 0001 (AF1) to select TIM2_CH1.

Timer configuration (TIM2)

  • TIM2->PSC: Set to 79 (1 MHz counter clock).
  • TIM2->ARR: Set to the desired frequency target (e.g., 999 for 1 kHz, 4544 for 220 Hz).
  • TIM2->CCR1: Set to half of ARR for a 50% square wave (e.g., 500 for 1 kHz).
  • TIM2->CCMR1: Set OC1M bits to 0110 (PWM Mode 1: active while CNT < CCR1), and set OC1PE to 1 (enable preload register).
  • TIM2->CCER: Set CC1E bit to 1 to enable output on Channel 1.
  • TIM2->CR1: Set CEN bit to 1 to enable the counter.
