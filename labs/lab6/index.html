Lab 6: IoT, Web Server, and SPI

Lab Report
An IoT device: an ESP8266 web server controlling an LED and reading a DS1722 temperature sensor over SPI.
Author

Eduardo Ambriz Lazo

Published

October 18, 2026

Introduction

In this lab, we made an Internet of Things (IoT) device that communicates with a temperature sensor over SPI, controls an LED, and serves a web page. The web page lets the user turn the LED on and off and adjust the resolution of the temperature readings. This lab took a total of 25 hours (there were some unexpected delays when a bunch of files were lost).

Below is some code outlining the logic for the temperature sensor, SPI communication, and the behavior of the site when interacting with the ESP module and the temp. sensor.

int inString(char request[], char des[]) {
    if (strstr(request, des) != NULL) {return 1;}
    return -1;

int updateLEDStatus(char request[])
{
    int led_status = 0;
    // The request has been received. now process to determine whether to turn the LED on or off
    if (inString(request, "ledoff")==1) {
        digitalWrite(LED_PIN, PIO_LOW);
        led_status = 0;
    }
    else if (inString(request, "ledon")==1) {
        digitalWrite(LED_PIN, PIO_HIGH);
        led_status = 1;
    }

    return led_status;
}

int updateRESStatus(char request[])
{
    int bitresstatus = 0;
    if (inString(request, "8bit")==1) {

    // Receive web request from the ESP
    char request[BUFF_LEN] = "                  "; // initialize to known value
    int charIndex = 0;
    // Keep going until you get end of line character
    while(inString(request, "\n") == -1) {
    // Wait for a complete request to be transmitted before processing
    while(!(USART->ISR & USART_ISR_RXNE));
    request[charIndex++] = readChar(USART);
}
    config = configread();
    msb = MSBread();
    lsb = LSBread();
    int led_status = updateLEDStatus(request); //get LED data
    resolution = updateRESStatus(request); //get resolution data
    float temp = numtotemp(msb,  lsb);
    char tempStr[50];

    sprintf(resStr,"Resolution is %d bits",resolution);

    if (led_status == 1)

SPI Communication Logic Trace

When the SPI communication is working properly, we should see the following logic trace in the waveform viewer. The following screenshot shows the expected behavior of the SPI communication between the MCU and the DS1722 temperature sensor. It should be noted that the button that triggered this trace is the “9 bits” button on the web server and the reading on the server said 25 degrees Celsius.

The top trace is the lsbRead function in my code, because looking at the MOSI sent (in blue) we see 0x01 which corresponds to the address byte for the LSB register. For MISO, we get FF which corresponds to floating high showing all high bits. For the second byte (pair of 8 bits) we get 00 on MOSI and 00 on MISO meaning a clock out. Basically, here we are querying the LSB register and reading 0x00 in the data byte.

In the middle transaction, MOSI sends 0x00, the address byte of the config register. MISO once again receives FF. The second byte is a dummy byte for MOSI (to clock in data from the DS1722) but MISO reads E2 which is exactly the decoding for 9 bits in our code for temperature resolution.

Lastly, we get a 0x02 in MOSI sent which corresponds to the address byte for the MSB register. This is followed by a MISO returned (in the second byte) of 0x19. In decimal, this hex value represents 25. This corresponds to the temperature reading of 25 degrees Celsius that was displayed on the web server. The integer part of the temperature is stored in the MSB register and the fractional part is stored in the LSB register. The LSB read earlier was 0x00, so there is no fractional part and the temperature is exactly 25 degrees Celsius.

The math also checks out: rawtemp = ((0x19 << 8) | 0x00) >> 4 = 0x1900 >> 4 = 0x0190 = 400, and 400 × 0.0625 = 25 degrees Celsius.

Conclusion

The design successfully read temperature data from the DS1722 temperature sensor and displayed it on a web server. The user was able to control the LED and change the resolution of the temperature readings through the web interface. The SPI communication between the MCU and the temperature sensor was verified through logic traces, confirming that the correct data was being sent and received.

Additionally, the project demonstrated the integration of IoT concepts with embedded systems, showcasing how microcontrollers can interact with sensors and web servers to create interactive applications. The lab provided valuable hands-on experience in working with SPI communication, web server implementation, and real-time data processing.

#include "stm32l4xx_hal.h"
#include <stdint.h>
#include <stdbool.h>

/* DS1722 Register Addresses */
#define DS1722_READ_LSB_TEMP   0x01
#define DS1722_READ_MSB_TEMP   0x02
#define DS1722_READ_CONFIG     0x00
#define DS1722_WRITE_CONFIG    0x80

/* Resolution Bitmasks (Config Bits 3..1) */
typedef enum {
    DS1722_RES_8BIT  = 0x00, /* 1.0°C resolution   (Conversion time ~75ms)  */
    DS1722_RES_9BIT  = 0x02, /* 0.5°C resolution   (Conversion time ~150ms) */
    DS1722_RES_10BIT = 0x04, /* 0.25°C resolution  (Conversion time ~300ms) */
    DS1722_RES_11BIT = 0x06, /* 0.125°C resolution (Conversion time ~600ms) */
    DS1722_RES_12BIT = 0x08  /* 0.0625°C resolution(Conversion time ~1200ms)*/
} DS1722_Resolution;

/**
* @brief  Reads the temperature from a DS1722 SPI sensor.
* @param  hspi     Pointer to SPI_HandleTypeDef structure (e.g., &hspi1)
* @param  cs_port  GPIO Port connected to DS1722 CE/CS pin (e.g., GPIOA)
* @param  cs_pin   GPIO Pin connected to DS1722 CE/CS pin (e.g., GPIO_PIN_4)
* @param  temp_out Pointer to float variable where temperature in °C will be stored
* @retval HAL_StatusTypeDef (HAL_OK on success)
*/
HAL_StatusTypeDef DS1722_ReadTemperature(SPI_HandleTypeDef *hspi, 
                                        GPIO_TypeDef *cs_port, 
                                        uint16_t cs_pin, 
                                        float *temp_out) 
{
    uint8_t tx_buf[3];
    uint8_t rx_buf[3] = {0};
    HAL_StatusTypeDef status;

    if (temp_out == NULL) {
        return HAL_ERROR;
    }

    // Step 1: Prepare Address and Dummy Bytes
    // DS1722 address byte bit 7 = 0 for Read operations.
    // Address 0x01 reads LSB, continuous clocking automatically reads MSB at 0x02.
    tx_buf[0] = DS1722_READ_LSB_TEMP;
    tx_buf[1] = 0x00; // Dummy byte to clock out LSB byte
    tx_buf[2] = 0x00; // Dummy byte to clock out MSB byte

    // Step 2: Assert Chip Enable / Chip Select (DS1722 CE is Active High)
    HAL_GPIO_WritePin(cs_port, cs_pin, GPIO_PIN_SET);

    // Step 3: Perform 3-byte SPI Transaction (Address + LSB + MSB)
    status = HAL_SPI_TransmitReceive(hspi, tx_buf, rx_buf, 3, HAL_MAX_DELAY);

    // Step 4: De-assert Chip Enable
    HAL_GPIO_WritePin(cs_port, cs_pin, GPIO_PIN_RESET);

    if (status != HAL_OK) {
        return status;
    }

    // Step 5: Convert Raw Sensor Output to °C
    // rx_buf[1] holds LSB (fractional part), rx_buf[2] holds MSB (integer/sign part)
    uint8_t raw_lsb = rx_buf[1];
    int8_t  raw_msb = (int8_t)rx_buf[2]; // Signed integer for negative temperatures

    // Combine raw registers: MSB is integer portion, LSB top 4 bits are fractional (1/16ths = 0.0625°C)
    float temperature = (float)raw_msb;
    temperature += (float)(raw_lsb >> 4) * 0.0625f;

    *temp_out = temperature;
    return HAL_OK;
}
